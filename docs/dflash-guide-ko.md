## 1. 한 줄 요약

> **AI 답변 속도를 2~3배 빠르게 만들어주는 "초안 작성 모델(draft model)"**
> 핵심은 **답변 품질이 전혀 손상되지 않는다**는 것.

일반적인 속도 최적화(양자화, 모델 축소)는 품질을 깎아서 속도를 얻습니다.
DFlash는 **수학적으로 동일한 출력 분포를 보장**하면서 속도만 올립니다. 부작용 없는 약인 셈이죠.

## 2. 쉽게 이해하는 원리

### 왜 LLM은 느릴까?

LLM은 글자를 **한 개씩** 생성합니다.

```
"오" → (무거운 계산) → "늘" → (무거운 계산) → "은" → ...
```

비유하자면 **책 100만 권짜리 창고를 글자 하나 쓸 때마다 전부 훑는 것**과 같습니다.
창고 한 바퀴에 10초가 걸리는데 결과물은 겨우 글자 하나입니다.

### DFlash의 아이디어: "눈치 빠른 비서 쓰기"

| 등장인물 | 정체 | 특징 |
|---|---|---|
| 👨‍🏫 교수님 | 진짜 큰 AI 모델 (target) | 똑똑하지만 매우 느림 |
| 👧 비서 | DFlash 초안 모델 (draft) | 덜 똑똑하지만 초고속 |

진행 방식:

1. 비서가 먼저 후루룩 씁니다 → *"오늘은 날씨가 참 좋네요"*
2. 교수님이 그걸 **한 번에 채점**합니다
3. *"오늘은 날씨가 참"* → 통과 ✅ / *"좋네요"* → 틀림, 교수님이 교정 ❌
4. 맞은 데까지 그대로 인정 + 보너스 토큰 1개를 덤으로 획득

**핵심:** 교수님은 창고를 **딱 한 번만** 돌았는데 글자는 **여러 개**를 얻었습니다.

```
기존:   창고 5바퀴 (50초) → 글자 5개
DFlash: 창고 1바퀴 (10초) → 글자 5개
```

### "비서가 틀리면 답이 이상해지지 않나요?"

아닙니다. 비서 제안은 **교수님이 인정할 때만** 통과되고, 조금이라도 다르면 즉시 버려집니다.
그래서 **최종 결과는 교수님이 혼자 쓴 것과 동일**합니다.

### DFlash만의 차별점

기존 speculative decoding(EAGLE 계열)은 **초안 모델도 한 글자씩** 썼기 때문에 초안 생성 자체가 느렸습니다.

DFlash는 **Block Diffusion** 방식입니다.

- 빈칸을 여러 개 그려놓고 `[ ][ ][ ][ ][ ]`
- **동시에 한 방에** 전부 채웁니다 ⚡

게다가 초안 모델은 큰 모델의 **중간 hidden state를 그대로 빌려 쓰고**, **출력 헤드(lm_head)도 재활용**합니다.
덕분에 몸집은 초소형인데 정확도가 높습니다.

## 3. 기술적으로 조금 더 깊게

### 핵심 루프 (`dflash/model.py`의 `dflash_generate`)

1. **블록 초기화** — 다음 `block_size`개 자리를 `mask_token_id`로 채움
2. **초안 제안** — 초안 모델이 target hidden state + 마스크 임베딩을 받아 블록 전체를 병렬 예측
3. **검증** — target 모델이 블록을 한 번의 forward로 검증
4. **채택 판정**
   - greedy(`temperature=0`): argmax 일치하는 앞부분까지 채택
   - sampling(`temperature>0`): **rejection sampling**으로 분포 동일성 보장
5. **보너스 토큰** — 틀린 자리는 target의 답으로 교체 (항상 최소 1개 전진 보장)
6. **KV 캐시 롤백** — `_crop_to()`로 채택 길이만큼만 남기고 잘라냄

### DFlash 2의 추가 요소

| 구성 요소 | 역할 |
|---|---|
| `GroupedDynamicCausalConv` | 블록 내부 토큰끼리 정보를 주고받는 동적 convolution |
| `CandidateSelector` | 자리마다 top-k 후보를 뽑고, 저차원 codebook(`predecessor` × `successor`)으로 "앞 토큰과 자연스럽게 이어지는지" 점수화 → 가장 그럴듯한 **경로**를 선택 |

단순 argmax보다 채택률이 크게 올라갑니다.

### 성능 지표

벤치마크가 출력하는 **acceptance length**(블록당 평균 채택 토큰 수)가 핵심 지표입니다.
이 값이 클수록 실제 속도 향상 폭이 큽니다.

## 5. 설치 및 사용법

### 준비물 체크

| 내 컴퓨터 | 사용 가능한 백엔드 |
|---|---|
| 🍎 맥 (M1~M4) | `mlx` ✅ |
| 🖥️ 엔비디아 GPU + 리눅스 | `transformers` ✅ |
| 💻 일반 윈도우 / 인텔맥 | ❌ 로컬 실행 불가 (서버 연결만 가능) |

> ⚠️ `cli.py`에 `cuda:0`이 하드코딩되어 있어 **transformers 백엔드는 NVIDIA GPU 필수**입니다. CPU 실행은 불가합니다.

### 설치

```bash
python -m venv .venv
source .venv/bin/activate     # 윈도우: .venv\Scripts\activate

pip install "dflash[local]"   # 로컬 추론 포함
# pip install dflash          # 서버 연결만 할 경우 (초경량)
```

`[local]`을 붙이면 플랫폼을 자동 판별합니다 — 맥이면 MLX, 리눅스면 PyTorch + Transformers.

> ⚠️ 의존성이 정확한 버전으로 핀 고정(`torch==2.13.0`, `transformers==5.15.0` 등)되어 있어 기존 환경과 충돌할 수 있습니다. **반드시 가상환경을 사용하세요.**

### 사용 — 맥 (MLX)

```bash
dflash generate mlx \
    --model mlx-community/Qwen3.8-27B-4bit \
    --draft z-lab/Qwen3.8-27B-DFlash2 \
    --draft-bits 4 --block-size 5 --reasoning xhigh \
    "파이썬으로 피보나치 짜줘"
```

### 사용 — 리눅스 (Transformers)

```bash
dflash generate transformers \
    --model meta-models/Muse-Glimmer-30B \
    --draft z-lab/Muse-Glimmer-30B-DFlash2 \
    --reasoning high --temperature 1 --top-p 0.95 --top-k 64 \
    "How many positive whole-number divisors does 196 have?"
```

### 사용 — OpenAI 호환 서버 (SGLang / vLLM)

```bash
dflash generate openai \
    --base-url http://127.0.0.1:8000 --model Qwen/Qwen3.8-27B \
    "질문 내용"
```

### 벤치마크

```bash
dflash benchmark mlx \
    --model mlx-community/Qwen3.8-27B-4bit \
    --draft z-lab/Qwen3.8-27B-DFlash2 \
    --dataset gsm8k --max-samples 128 --block-size 5 --draft-bits 4
```

### 주요 옵션

| 옵션 | 의미 |
|---|---|
| `--model` | 실제 모델 (target) |
| `--draft` | DFlash 초안 모델 (draft) — 로컬 백엔드는 필수 |
| `--block-size` | 한 번에 제안할 토큰 수 (양자화 모델은 `<= 5` 권장) |
| `--draft-bits` | 초안 모델 양자화 비트 (4 또는 8) |
| `--reasoning` | 모델별 추론 강도 (`low`/`medium`/`high`/`xhigh`) |
| `--temperature` | 0이면 greedy |

### 🔑 가장 중요한 규칙

> **target과 draft는 반드시 짝이 맞아야 합니다.**
> `Qwen3.8-27B` → `Qwen3.8-27B-DFlash2`
> 아무 초안 모델이나 붙일 수 없고, README의 지원 목록에서 골라야 합니다.

## 6. 플러그인? 스킬? MCP?

### 답: **셋 다 아닙니다.** 평범한 **파이썬 패키지(라이브러리 + CLI)**입니다.

| 종류 | 설명 | DFlash |
|---|---|---|
| 🔌 플러그인 | 특정 앱에 끼워 넣는 확장 기능 | ❌ |
| 🎯 스킬 | AI에게 작업 방식을 알려주는 지침서(마크다운) | ❌ |
| 🔗 MCP | AI가 외부 도구를 쓰게 해주는 표준 연결 규격 | ❌ |
| 📦 파이썬 패키지 | `pip install`로 설치해 쓰는 프로그램 | ✅ |

### 어느 계층에 있나

```
🎨 앱 / 챗봇 UI              ← React, PHP는 여기
     ↕
🔗 MCP / 에이전트 프레임워크
     ↕
🧠 LLM 추론 엔진 (vLLM, SGLang, MLX)  ← 💥 DFlash는 여기 💥
     ↕
🔧 GPU
```

**한마디로 "엔진 튜닝 부품"**입니다. MCP나 스킬보다 훨씬 아래층입니다.

> 💡 다만 **DFlash 서버를 MCP 서버로 감싸는 것은 가능**합니다.
> DFlash가 붙은 추론 서버를 띄우고, 그 앞에 MCP 서버를 만들어 "로컬 모델에게 물어보기" 도구를 노출하는 방식입니다.

## 7. API 토큰이 필요한가?

### 결론: **기본적으로 전혀 필요 없습니다.**

모든 연산이 내 컴퓨터에서 이뤄지므로 OpenAI/Anthropic 같은 유료 API 키가 필요 없고, **사용료도 0원**입니다.

### 예외 ① 허깅페이스 토큰 (무료)

Llama, Gemma 등 일부 모델은 약관 동의가 필요해 로그인이 필요합니다.

```bash
pip install huggingface-hub
hf auth login
```

Qwen 계열은 대부분 그냥 받아집니다.

### 예외 ② ⚠️ 코드 확인 결과 — 중요

`dflash/benchmark.py`의 `send_openai()` 함수는 **`Authorization` 헤더를 전혀 보내지 않습니다.**

| 대상 | 동작 |
|---|---|
| 내가 띄운 vLLM / SGLang 서버 | ✅ 정상 동작 |
| 실제 OpenAI / Anthropic 클라우드 API | ❌ 불가 (인증 불가) |

즉 `openai` 백엔드는 **"OpenAI 회사에 연결"하는 것이 아니라 "OpenAI와 동일한 형식의 내 로컬 서버"에 연결**하는 용도입니다. 이름이 다소 헷갈립니다.

> 애초에 클라우드 API에는 DFlash를 적용할 수 없으므로, 인증 헤더 추가는 실익이 없습니다.

## 9. 로컬 에이전트 구축에 도움이 될까

### 결론: **매우 도움이 됩니다. 사실상 에이전트가 최대 수혜자입니다.**

### 왜인가

일반 챗봇은 사람이 읽는 속도라 조금 느려도 견딜 만합니다. 하지만 에이전트는 다릅니다.

```
생각 → 도구 호출 → 결과 확인 → 다시 생각 → 또 도구 호출 → ...
```

**한 번의 지시에 LLM을 10~20번 호출**합니다. 각 호출이 3배 빨라지면 **전체 작업 시간이 3배 단축**됩니다.

### 게다가 에이전트 출력은 채택률이 높습니다

DFlash는 **예측 가능한 패턴일수록** 잘 맞춥니다. 에이전트 출력은 대부분 이런 형태입니다.

```json
{"tool": "search", "arguments": {"query": "..."}}
```

```python
def process_data(items):
    result = []
    for item in items:
```

구조화된 텍스트(JSON, 코드, 들여쓰기)는 초안 모델이 거의 다 맞춥니다.
창작 글쓰기보다 **채택률이 훨씬 높아 속도 이득이 커집니다.**

### 권장 구성

```
[에이전트 코드]  ← LangChain, 자체 구현 등 무엇이든
      ↓ HTTP (OpenAI 호환 형식)
[vLLM 또는 SGLang 서버 + DFlash]
      ↓
   내 GPU / 맥
```

에이전트 프레임워크 코드는 **한 줄도 수정할 필요 없습니다.** `base_url`만 내 서버로 바꾸면 됩니다.

### 한계 (솔직하게)

| 항목 | 설명 |
|---|---|
| ⚠️ 프롬프트 읽기(prefill) | 빨라지지 않음. **생성 단계(decode)만** 가속 |
| ⚠️ 동시 사용자 多 | 동시 요청 1건일 때 효과 최대, 수백 명 동시 접속이면 효과 감소 |
| ⚠️ 추가 메모리 | 초안 모델도 메모리를 차지 (VRAM이 빠듯하면 고려 필요) |
| ⚠️ 모델 제한 | 짝이 맞는 초안 모델이 있는 모델만 사용 가능 |

에이전트는 **단독 사용 + 긴 출력**이 많아 거의 최적의 적용처입니다.

### 🥈 2. 니치 SaaS — "속도가 곧 제품"

> 손님은 DFlash를 몰라도 됩니다. **"왜 이렇게 빠르지?"** 하고 쓰면 그만입니다.

#### 후보 4개 (적합도 순)

**① 🎙️ 음성 AI (상담, 통역, 낭독)**

음성은 지연에 가장 민감합니다.

```
응답 1초 → "대화 같다"
응답 3초 → "고장난 줄"
```

지연을 1/3로 줄이면 제품 등급 자체가 달라집니다.
구체적 아이템: 병원 예약/문진 자동응대(환자정보 로컬 = 이중 무기), 실시간 회의 통역, 콜센터 상담원 보조.

**② ⌨️ 사내 전용 코드 어시스턴트 — 최우선 추천**

무기 3개가 모두 발동합니다.

| 무기 | 발동 방식 |
|---|---|
| ⚡ 속도 | 코드는 패턴이 뻔해 **초안 채택률 최상** |
| 🔒 로컬 | **"소스코드가 외부로 나가지 않습니다"** = 개발팀장이 가장 듣고 싶은 말 |
| 💰 비용 | 인원이 많을수록 서버 1대가 유리 |

타겟: 개발자 20~200명 규모의 보안 민감 조직(금융권 개발조직, 방산, 게임사 등).

**③ 🎮 게임 NPC / 인터랙티브 콘텐츠**
지연이 곧 재미 손실. 유저 기기 로컬 실행 시 서버비 0원. 단, 게임사 영업 난이도와 사양 편차가 문제.

**④ 📄 문서 대량 처리 (계약서 검토, 리서치 요약)**
기밀문서라 로컬 필수, 물량이 많아 속도 = 처리량. 단, 리걸테크 경쟁이 치열.

#### SaaS의 냉정한 현실

| 리스크 | 설명 |
|---|---|
| 💸 GPU 고정비 | 손님이 없어도 비용 발생 |
| ⏳ 긴 리드타임 | 제품 개발 + 마케팅에 최소 6~12개월 |
| 🥊 경쟁 | 대형 업체가 같은 기능을 무료로 낼 수 있음 |

> 💡 **1번(컨설팅)으로 현금을 벌면서 2번을 만드는 것이 정석입니다.**

### 🏰 4. 커스텀 초안 모델 훈련 — 진짜 해자

#### ⚠️ 저장소 분석 결과: **훈련 코드가 없습니다.**

이 저장소에는 추론(사용) 코드만 있고, **초안 모델을 만드는 학습 코드는 공개되어 있지 않습니다.**

이것이 기회인 이유:

```
회사 A: "우리 데이터로 파인튜닝한 전용 모델을 씁니다"
        ↓
   그 모델용 DFlash 초안 모델은 세상에 존재하지 않음
        ↓
   DFlash 적용 불가 → 느린 채로 사용
```

여기를 뚫으면 **누구도 따라할 수 없는 해자**가 생기고, 고객사는 강하게 락인됩니다.

#### 하지만 난이도 최상

| 필요 | 현실 |
|---|---|
| 논문 재현 능력 | arXiv 논문 기반 구조 직접 구현 |
| GPU 학습 자원 | 상당한 대여 비용 |
| 학습 데이터 | 대상 모델의 출력을 대량 수집 |
| 시간 | 최소 6~12개월 |

#### 현실적 접근

```
지금 당장 ❌ → 1~2번으로 수익을 내며 병행 연구
             → "우리 모델용도 되나요?" 문의가 쌓임
             → 수요 검증 후 본격 투자 ✅
```

**수요 확인 전에 뛰어들지 마세요.**

## 11. React / PHP로 만들 수 있나

### ❌ A. DFlash 자체를 React/PHP로 재구현

**현실적으로 불가능합니다.**

DFlash의 핵심은 **GPU에서의 대규모 행렬 연산**이며, CUDA/Metal 같은 저수준 기술이 필요합니다.

- PHP에는 GPU 텐서 라이브러리가 없습니다
- React는 브라우저 UI 도구라 수십 GB 모델을 올릴 수 없습니다

> 비유하면 "엑셀로 3D 게임 만들기"와 비슷합니다.

### ✅ B. React/PHP로 DFlash를 **활용하는 서비스** 만들기

**완전히 가능하며, 오히려 이것이 정석입니다.**

```
┌──────────────────────────────────────┐
│ 🎨 React — 채팅 화면, 스트리밍 출력    │  ← 직접 개발
└────────────┬─────────────────────────┘
             │ HTTP
┌────────────▼─────────────────────────┐
│ 🐘 PHP — 로그인, DB, 대화기록, 결제    │  ← 직접 개발
└────────────┬─────────────────────────┘
             │ HTTP (OpenAI 호환 형식)
┌────────────▼─────────────────────────┐
│ 🧠 vLLM/SGLang + DFlash (파이썬)      │  ← 실행만
└──────────────────────────────────────┘
```

핵심은 DFlash 서버가 **OpenAI와 동일한 형식**으로 통신한다는 점입니다.
PHP, Node, Go 무엇이든 **HTTP 요청만 보낼 수 있으면 연결됩니다.**

#### PHP 예시

```php
$ch = curl_init('http://127.0.0.1:8000/v1/chat/completions');
curl_setopt_array($ch, [
    CURLOPT_POST => true,
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER => ['Content-Type: application/json'],
    CURLOPT_POSTFIELDS => json_encode([
        'model' => 'Qwen/Qwen3.8-27B',
        'messages' => [['role' => 'user', 'content' => $userInput]],
    ]),
]);
$answer = json_decode(curl_exec($ch), true)['choices'][0]['message']['content'];
```

이것이 전부입니다. PHP는 DFlash가 쓰이는지 알 필요조차 없고, 단지 응답이 빨라질 뿐입니다.

#### React 쪽

`fetch`로 `stream: true` 옵션을 주고 **SSE 스트리밍**으로 토큰을 흘려보내면 ChatGPT처럼 타이핑 효과가 납니다.
DFlash 덕분에 그 타이핑 속도가 눈에 띄게 빨라집니다.

#### 📌 주의

> **PHP/React는 "GPU가 있는 컴퓨터"를 대체할 수 없습니다.**
> 어딘가에는 반드시 파이썬 + GPU 추론 서버가 있어야 하며, 그 앞에 UI(React)와 백엔드(PHP)를 붙이는 구조입니다.

## 13. 최종 요약표

| 질문 | 답 |
|---|---|
| **이게 뭐야?** | LLM 답변 속도를 2~3배 올리는 초안 모델. **품질 손실 0** |
| **설치는?** | `pip install "dflash[local]"` — 맥은 MLX, 리눅스+NVIDIA는 Transformers |
| **플러그인/스킬/MCP?** | 전부 아님. **파이썬 패키지**이자 추론 엔진 계층의 튜닝 부품 |
| **API 토큰?** | **불필요.** 전부 로컬, 사용료 0원 (게이트 모델만 HF 토큰) |
| **왜 유명해?** | 품질 손실 0 + vLLM/SGLang 채택 + 다수 모델 지원 + 맥 지원 + MIT |
| **에이전트에 도움?** | **최적의 적용처.** 호출이 많고 출력이 구조적이라 효과 극대화 |
| **수익화?** | 기술이 아니라 **"보안 × 속도"**를 팔 것. 온프레미스 구축 대행부터 시작 |
| **React/PHP?** | 엔진 재구현은 ❌ / **서비스 개발은 ✅** — HTTP로 연결하면 끝 |

## ⚠️ 알아두면 좋은 주의사항 모음

1. **target과 draft 모델은 반드시 짝을 맞출 것** — 지원 목록 확인 필수
2. **transformers 백엔드는 NVIDIA GPU 전용** (`cuda:0` 하드코딩, CPU 불가)
3. **가상환경 필수** — 의존성이 정확한 버전으로 고정되어 있음
4. **`openai` 백엔드는 인증 헤더를 보내지 않음** — 로컬 서버 전용
5. **학습(훈련) 코드는 이 저장소에 없음** — 추론 전용
6. **테스트 코드 없음** — CI는 빌드/설치 스모크 테스트 수준
7. 모델 다운로드 용량이 큼 (27B 4bit 기준 수십 GB) — **디스크 여유 확인**
